# SPEC — yt-trend-radar

> **상태: 확정 (v1.0, 2026-07-30) — D1~D7 전체 결정 완료 (§8). 변경 시 SPEC → PLAN → DESIGN → TASK 순서로 역추적 갱신.**

## 1. 목표

유튜브 공식 Trending 페이지 폐지(2025-07) 이후 빈 자리를 채우는 **카테고리별 유튜브 트렌드 발견 서비스**.
사용자가 관심 카테고리(음식/여행 × 국내/해외 등)를 골라 **지금 뜨는 영상·유튜버**와 **새로 떠오르는 영상·유튜버**를 확인한다.

- 공개 웹서비스 (한국 사용자 중심, 한국어 UI)
- 트렌드는 유튜브가 주지 않으므로 **자체 산출 지표**로 계산 (핵심 차별점)
- 초기 비용 0원 구조: 무료 티어 조합으로 운영 시작

## 2. 대상 사용자

| 사용자 | 니즈 |
|--------|------|
| 일반 시청자 | 알고리즘 피드 밖에서 카테고리별 "요즘 뜨는 것" 탐색 |
| 크리에이터/마케터 | 내 카테고리의 급상승 채널·소재 파악 |

## 3. 기능 요구사항 (FR)

### FR-1 카테고리 체계 (확장형)
- 카테고리는 **데이터(설정 파일/DB)로 정의**하며 코드 수정 없이 추가 가능해야 한다.
- 계층 구조: 대분류 × 태그 조합 (예: `음식 > 해외`, `여행 > 국내`).
- 초기 시드 카테고리 (2026-07-30): **음식, 여행, IT·테크, 바이브코딩·AI, 브이로그·일상, 운동·건강** — 6개 대분류 × 국내/해외 태그.
  - `바이브코딩·AI` 는 사용자 요청으로 추가(2026-07-30). tech 에서 개발·코딩·AI 키워드를 이관하고
    가중치를 1.1 로 둬 겹치는 소재에서 우선한다. **확장형 체계의 첫 실전 검증** — 코드 수정 없이 YAML 로 추가됐다.
- 영상/채널 → 카테고리 매핑: 제목·태그·설명 키워드 규칙 기반으로 시작. ❓ LLM 분류 도입 여부/시점.

### FR-2 지금 뜨는 영상 (Trending Videos)
- 카테고리별, 최근 N일(기본 7일) 내 업로드 영상 중 **조회수 증가 속도(velocity)** 상위 랭킹.
- 표시: 썸네일, 제목, 채널명, 조회수, 자체 급상승 점수, 업로드 시점. 클릭 시 유튜브로 이동.

### FR-3 신규 뜨는 영상 (Rising Videos)
- 구독자 규모 대비 성과가 비정상적으로 높은 영상 (예: 조회수/구독자 비율 + 가속도).
- 소형 채널의 "터진 영상"을 조기에 노출하는 것이 목적.

### FR-4 지금 뜨는 유튜버 (Trending Channels)
- 카테고리별 구독자·조회수 성장률 상위 채널 랭킹 (주간 기준).

### FR-5 신규 뜨는 유튜버 (Rising Channels)
- 구독자 **10만 이하** (확정, 2026-07-30) + 성장률 상위 채널.

### FR-6 데이터 수집 파이프라인
- 크론 기반 수집기 (하루 2~4회):
  - 추적 채널 새 영상 감지: **채널 RSS 피드** (쿼터 0)
  - 영상 통계 스냅샷: `videos.list` 50개 배치 (1유닛/50개)
  - 채널 통계 스냅샷: `channels.list` 50개 배치 (1유닛/50개)
  - 신규 채널/영상 발굴: `search.list` 일 예산제 (❓ 일 예산: 예 60회 = 6,000유닛)
- 일 쿼터 10,000유닛 초과 금지 — 예산 초과 시 수집 축소, 서빙은 영향 없음.
- 시드 채널 부트스트랩 (확정, 2026-07-30): **혼합** — 카테고리별 수동 시드 10~20개 + 초기 2주 `search.list` 예산 집중 발굴.

### FR-7 트렌드 지수 산출
- 자체 지표임을 UI에 명시 ("자체 산출 급상승 점수").
- **산식: B. 정규화 velocity (확정, 2026-07-30)**
  - `score = Δ값 / (Δ시간h × max(구독자, floor)^α)`, floor = 1,000
  - "지금 뜨는"(FR-2/4)은 α를 낮춰 절대 규모 반영, "신규 뜨는"(FR-3/5)은 α를 높여 소형 채널 발굴 — 같은 산식의 파라미터 차이로 구현
- **α 확정값 (2026-08-03 시연으로 교정)**

  | 보드 | α | 측정 대상 | 비고 |
  |------|---|-----------|------|
  | 지금 뜨는 영상/유튜버 | **0.25** | Δ조회수 | 규모를 반영하되 완만한 핸디캡 |
  | 신규 뜨는 영상 | **1.00** | Δ조회수 | 구독자 1명당 조회수 = 규모 중립 |
  | 신규 뜨는 유튜버 | **1.00** | Δ구독자 | + 구독자 10만 이하 (D7) |

  **α ≥ 1.0 은 규약이다.** Δ가 구독자에 비례할 때 `score ∝ 구독자^(1-α)` 이므로,
  α<1 이면 "신규 뜨는"도 결국 규모 순이 된다 (α=0.7로 시연했을 때 실제로 그랬다).
  α=1.0 에서만 "구독자 대비 성과"라는 정의가 성립한다. 테스트가 이 관계를 강제한다.
- 산출 구간: 영상 48시간, 채널 7일. **Δ시간은 실측**한다 (cron 지연 시에도 정확해야 함).
- 지금 뜨는 영상은 **업로드 7일 이내**만 대상 — 오래된 영상이 누적 조회수로 눌러앉지 않게.
- 스냅샷 시계열(30일 윈도우)에서 계산, 콜드스타트 최소 2주 수집 후 오픈.

### FR-8 웹 프론트
- 홈: 카테고리 선택 → 4개 랭킹 보드 (FR-2~5).
- **채널 상세 페이지 MVP 포함 (확정, 2026-07-30)**: 구독자·조회수 성장 그래프(30일), 소속 카테고리, 최근 급상승 영상 목록.
- 반응형, 라이트/다크 모드. **UI 규격은 `docs/DESIGN.md`가 단일 진실** (SDD 규칙).

### FR-9 운영 콘솔 (admin) — 유지보수
- 운영자가 **현재 상태와 이상 징후를 한 화면에서** 확인하고, 유지보수 절차를 순서대로 실행할 수 있어야 한다.
- 표시: 카테고리·시드 수, RSS 검증 통과율, 스냅샷/랭킹 적재량, 마지막 수집 시각, 오늘 쿼터 사용량.
- **자동 점검**: 시드 공백 카테고리, 검증 기록 노후, 통과율 저조, 수집 중단(12h), 보관정책 위반(30일 초과 행), 랭킹 공백, 쿼터 임박.
- **런북**: 카테고리 추가 → 시드 발굴(`--only`) → DB 동기화 → RSS 검증 → 검토·상황판 갱신 → purge 순서와 실행 명령.
- **성격 (확정, 2026-07-30)**: **읽기 전용 산출물 + 러너블**. 웹에서 작업을 트리거하지 않는다 —
  트리거는 인증과 service key 를 쓰는 서버 라우트를 요구하며, 그것은 새 보안 표면이다 (NFR-3 위반 위험).
  버튼 실행이 필요해지면 **별도 Phase 로 인증·감사로그와 함께** 설계한다.
- 정기 실행: 수집 cron(하루 3회) 직후 RSS 검증·리포트 생성을 같은 워크플로에서 이어 실행한다.

## 5. 기술 스택

| 레이어 | 선택 | 비고 |
|--------|------|------|
| 프론트/서빙 | Next.js (App Router) + Vercel | ⚠️ 이 PC 빌드는 포터블 Node 22 + typescript@5 사용 (워크스페이스 메모리) |
| 수집기 | Python 스크립트 + GitHub Actions cron (하루 2~4회) | 로컬 harness 모드로도 실행 가능해야 함 (TDD) |
| DB | **Supabase (Postgres) 무료 티어 (확정, 2026-07-30)** — Vercel 서버리스와 궁합, 수집기(Actions)에서도 접근 가능 | 30일 롤링으로 500MB 한도 관리 |
| API | YouTube Data API v3 (일 10,000유닛) + 채널 RSS | 키는 GitHub Actions Secrets + 로컬 `.env` |
| 분류 | 키워드 규칙 (초기) → LLM 옵션 (후속) | |

## 6. 데이터 모델 (개요 — PLAN에서 상세화)

- `channels` — 채널 메타 + 카테고리 매핑
- `channel_snapshots` — 구독자/총조회수 시계열 (30일 롤링)
- `videos` — 영상 메타 (30일 롤링)
- `video_snapshots` — 조회수 시계열 (30일 롤링)
- `categories` — 카테고리 정의 (계층 + 매핑 키워드) ← **확장형 체계의 핵심**
- `trend_scores` — 산출된 랭킹 캐시 (프론트는 이것만 읽음)

## 7. 제약 조건

- YouTube 공식 카테고리 트렌딩 API 부재 → 자체 산출 필수 (전제)
- `search.list` 100유닛/회 → 발굴은 예산제로만
- 콜드스타트: 오픈 전 최소 2주 수집 필요
- 무료 티어 한도: GitHub Actions 분량, Supabase 500MB — 30일 롤링으로 관리
- 한국어 Windows 개발 환경: `PYTHONUTF8=1`, `encoding="utf-8"` 명시
