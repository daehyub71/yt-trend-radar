## 1. 기반 선택

`dataviz` 스킬의 **검증된 기본 팔레트를 그대로 채택**한다. 자체 브랜드 색이 아직 없고,
기본 팔레트는 라이트/다크 양 모드에서 게이트를 통과한 상태로 문서화돼 있다.
브랜드 팔레트가 정해지면 `references/palette.md` 구조에 값만 갈아끼우고 전면 재검증한다.

표면색(검증 기준면):

| 역할 | 라이트 | 다크 |
|------|--------|------|
| 페이지 | `#f9f9f7` | `#0d0d0d` |
| 카드/차트 표면 | `#fcfcfb` | `#1a1a19` |
| 보조 표면 (칩·입력) | `#f3f2ee` | `#232322` |

잉크·크롬:

|------|--------|------|
| 주 텍스트 | `#0b0b0b` | `#ffffff` |

## 2. 채널 규모(티어) — 순서형 램프

채널 규모는 **순서가 있는 크기**이므로 categorical 이 아니라 **순서형(ordinal) 단일 색상 램프**를 쓴다.

| 티어 | 범위 | 라이트 | 다크 |
|------|------|--------|------|
| micro | 1천~1만 | `#86b6ef` (step 250) | `#184f95` (step 600) |
| small | 1만~10만 | `#5598e7` (350) | `#256abf` (500) |
| mid | 10만~100만 | `#2a78d6` (450) | `#3987e5` (400) |
| large | 100만+ | `#184f95` (600) | `#86b6ef` (250) |

칩 텍스트는 램프 색이 아니라 **더 진한 잉크 단계**를 쓴다(텍스트는 텍스트 토큰 원칙):
라이트 `#184f95`/`#184f95`/`#1c5cab`/`#104281`, 다크 `#86b6ef`/`#9ec5f4`/`#b7d3f6`/`#cde2fb`.

### 검증 기록 (2026-07-30)

```
node scripts/validate_palette.js "#86b6ef,#5598e7,#2a78d6,#184f95" \
     --mode light --surface "#fcfcfb" --ordinal
  [PASS] Lightness monotone / [PASS] Adjacent ΔL >= 0.06
  [PASS] Light-end contrast  #86b6ef 2.06:1  / [PASS] Single hue (spread 3°)
  → ALL CHECKS PASS

node scripts/validate_palette.js "#184f95,#256abf,#3987e5,#86b6ef" \
     --mode dark --surface "#1a1a19" --ordinal
  [PASS] Lightness monotone / [PASS] Adjacent ΔL >= 0.06
  [PASS] Light-end contrast  #184f95 2.15:1  / [PASS] Single hue (spread 3°)
  → ALL CHECKS PASS
```

### 탈락안과 사유 (실제 계산 결과)

| 안 | 검증 결과 | 탈락 사유 |
|----|-----------|-----------|
| **A. 램프 100/200/300/400** (`#cde2fb,#9ec5f4,#6da7ec,#3987e5`) | `[FAIL] Light-end contrast #cde2fb 1.29:1 — below 2:1 floor` | 가장 밝은 단계가 표면과 구분되지 않는다. 순서형은 sequential 과 달리 **가장 밝은 단계도 2:1 을 넘겨야** 한다(마크가 "거의 0"이 아니라 이산적 등급이므로) |
| **B. categorical 4색을 티어에 사용** (`#2a78d6,#eb6834,#1baf7a,#eda100`) | `[FAIL] Normal-vision floor #eda100↔#eb6834 ΔE 13.7 (<15)` + `[WARN] Contrast` | ① all-pairs 게이트를 통과하지 못한다(노랑↔주황) ② 애초에 **티어는 순서가 있는 값**이라 색상 회전은 순서를 감추는 오표현이다 |

## 2b. 상태색 — 검증 판정 (텍스트 대비 실측)

RSS 검증 판정은 **본문 크기 텍스트**로 표시하므로 차트 마크의 3:1 기준이 아니라
**WCAG 텍스트 기준(AA 4.5:1)** 으로 골랐다. 계산 결과(2026-07-30):

| 역할 | 색 | 표면 | 대비 | 판정 |
|------|----|------|------|------|
| 통과 (라이트) | `#006300` | `#fcfcfb` | 7.35:1 | AA PASS |
| 통과 (다크) | `#0ca30c` | `#1a1a19` | 5.19:1 | AA PASS |
| 탈락 (라이트) | `#d03b3b` | `#fcfcfb` | 4.68:1 | AA PASS |
| ~~탈락 (다크)~~ | ~~`#d03b3b`~~ | `#1a1a19` | 3.62:1 | **AA 미달 → 탈락** |
| 탈락 (다크) | `#e66767` | `#1a1a19` | 5.39:1 | AA PASS |
| 한글없음 경고 (라이트) | `#8a5a00` | `#fcfcfb` | 5.77:1 | AA PASS |
| 한글없음 경고 (다크) | `#fab219` | `#1a1a19` | 9.49:1 | AA PASS |

즉 다크 모드의 탈락색은 status-critical(`#d03b3b`)을 그대로 쓰지 않고 한 단계 밝은
`#e66767`(categorical red 다크 스텝)로 **의도적으로 교체**했다 — 마크가 아니라 텍스트이기 때문이다.
라이트 경고색도 마크용 `#fab219`(1.79:1) 대신 어두운 `#8a5a00`을 텍스트에 쓴다.
판정은 색 + 아이콘(✅/❌/⚠) + 수치(`9/15 · 60%`) 3중 인코딩이다.

## 3. 마크 규격

- **티어 칩**: 9×9px 라운드 스와치(2px radius) + 티어 한글 라벨. **색 단독 전달 금지** — 칩 옆에
  항상 구독자 수를 tabular-nums 로 병기한다(색·라벨·숫자 3중 인코딩).
- **분포 바**: 높이 8px, radius 4px, 세그먼트 사이 **2px 표면 간격**. 바 아래에
  스와치+라벨+개수 범례를 반드시 동반한다(바만으로는 어떤 색이 어떤 티어인지 알 수 없다).
- **진행 바**(진행 대시보드): 높이 8px, radius 4px, 트랙은 grid 토큰, 채움은 액센트.
  0%는 `min-width:0`으로 잔여 픽셀을 남기지 않는다.
- **표**: 헤어라인 구분선(grid), 마지막 행은 구분선 없음. 숫자 열은 우측 정렬 + `tabular-nums`.
- **상태(경고) 색**: `#fab219` (라이트 표면 대비 1.79:1). categorical 게이트 **비적용 대상**이며,
  3:1 미달은 **아이콘(⚠) + 라벨 문구 의무 동반**으로 면제한다(색 단독으로 의미를 싣지 않는다).
  경고 행 배경은 `color-mix(in oklab, var(--warn) 8%, transparent)` — 배경만으로 판단시키지 않는다.

### 점검 항목 (운영 콘솔)

- 좌측 3px 세로 스트라이프로 심각도를 싣고(`ok`/`warn`/`bad`/`na`), **아이콘(✅⚠️❌—) + 문구**를
  항상 동반한다. 배경 채색은 쓰지 않는다 — 점검 항목이 여러 개 쌓이면 배경색이 페이지를 지배한다.
- 각 항목은 **무엇이 문제인지(what) → 왜 문제인지(detail) → 실행할 명령(fix)** 3단으로 쓴다.
  상태만 보여주고 조치를 알려주지 않는 상황판은 반쪽이다.
- 정상 항목도 숨기지 않고 표시한다(예: "보관 정책 준수"). 무엇이 점검됐는지 알 수 있어야 한다.
- 임계값은 코드 상단 상수로 두고 근거를 `docs/PLAN.md §4b` 표에 남긴다.

### 토큰 정의점

코드 상의 단일 정의점은 `tools/_theme.py` 다 (3개 생성기가 공유). 값의 **근거와 검증 기록은
이 문서**가 소유한다. 값을 바꾸려면 이 문서 → `validate_palette.js` 재실행 → `_theme.py` 순서.

## 4. 상호작용 (내부 도구)

- 필터는 **차트/표 위 한 줄**에 모으고 sticky 로 고정한다.
- 토글 버튼은 `aria-pressed` 로 상태를 노출하고, 같은 값을 다시 누르면 해제한다.
- 검색은 채널명·핸들·채널ID를 함께 훑는다(대소문자 무시).
- 필터 결과가 0건이면 표를 숨기고 안내 문구를 보여준다 — 빈 표를 남기지 않는다.
- 포커스는 `:focus-visible` 로 2px 액센트 아웃라인.
- **외부 링크는 새 탭 + `rel="noopener"`**. 채널명·영상·정보 세 경로를 제공해
  검토자가 유튜브에서 즉시 확인할 수 있게 한다.

## 6. 서비스 UI (웹 프론트) — **P5 에서 작성**

아직 정하지 않았다. P5 착수 시 이 절에 다음을 확정하고, 그 전에는 UI 코드를 쓰지 않는다.

- [ ] 카테고리 6개의 표현 방식 (탭 vs 칩 vs 사이드) — 확장형 체계라 **개수가 늘어난다는 전제**로 설계
- [ ] 4개 랭킹 보드(지금 뜨는/신규 뜨는 × 영상/유튜버) 레이아웃과 카드 규격
- [ ] 썸네일 비율 처리 (16:9 롱폼 vs 9:16 Shorts 혼재)
- [ ] 급상승 점수의 시각 표현 — 절대 숫자를 그대로 노출하지 않는다(자체 지표임을 문구로 명시)
- [ ] 채널 상세의 30일 성장 그래프 폼 (dataviz form heuristic 으로 선택, 임의 선정 금지)
- [ ] 국내/해외 축의 표현
- [ ] YouTube 브랜딩·링크 표기 규격 (ToS 요구사항)
- [ ] 문구 규칙 — "자체 산출 급상승 점수" 등 지표 성격 고지 문구
- [ ] 서비스 팔레트 재검증 기록 (브랜드 색 도입 시)
