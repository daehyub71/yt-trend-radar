## 1. 기반 선택

`dataviz` 스킬의 **검증된 기본 팔레트를 그대로 채택**한다. 자체 브랜드 색이 아직 없고,
기본 팔레트는 라이트/다크 양 모드에서 게이트를 통과한 상태로 문서화돼 있다.
브랜드 팔레트가 정해지면 `references/palette.md` 구조에 값만 갈아끼우고 전면 재검증한다.

표면색(검증 기준면):

| 역할 | 라이트 | 다크 |
|------|--------|------|
| 페이지 | `#f9f9f7` | `#0d0d0d` |
| 카드/차트 표면 | `#fcfcfb` | `#1a1a19` |
| 보조 표면 (칩·입력) | `#f3f2ee` | `#232322` |

잉크·크롬:

| 역할 | 라이트 | 다크 |
|------|--------|------|
| 주 텍스트 | `#0b0b0b` | `#ffffff` |
| 보조 텍스트 | `#52514e` | `#c3c2b7` |
| 뮤트(라벨) | `#898781` | `#898781` |
| 그리드(헤어라인) | `#e1e0d9` | `#2c2c2a` |
| 룰(구분선) | `#c3c2b7` | `#383835` |
| 테두리 | `rgba(11,11,11,.10)` | `rgba(255,255,255,.10)` |
| 액센트 | `#2a78d6` | `#3987e5` |

다크는 자동 반전이 아니라 **별도 선택값**이며, 토큰 레벨에서 교체한다
(`@media (prefers-color-scheme: dark)` + `:root[data-theme=…]` 양쪽 선언 — 토글이 OS 설정을 양방향으로 이겨야 한다).

## 2. 채널 규모(티어) — 순서형 램프

채널 규모는 **순서가 있는 크기**이므로 categorical 이 아니라 **순서형(ordinal) 단일 색상 램프**를 쓴다.

| 티어 | 범위 | 라이트 | 다크 |
|------|------|--------|------|
| micro | 1천~1만 | `#86b6ef` (step 250) | `#184f95` (step 600) |
| small | 1만~10만 | `#5598e7` (350) | `#256abf` (500) |
| mid | 10만~100만 | `#2a78d6` (450) | `#3987e5` (400) |
| large | 100만+ | `#184f95` (600) | `#86b6ef` (250) |

칩 텍스트는 램프 색이 아니라 **더 진한 잉크 단계**를 쓴다(텍스트는 텍스트 토큰 원칙):
라이트 `#184f95`/`#184f95`/`#1c5cab`/`#104281`, 다크 `#86b6ef`/`#9ec5f4`/`#b7d3f6`/`#cde2fb`.

### 검증 기록 (2026-07-30)

```
node scripts/validate_palette.js "#86b6ef,#5598e7,#2a78d6,#184f95" \
     --mode light --surface "#fcfcfb" --ordinal
  [PASS] Lightness monotone / [PASS] Adjacent ΔL >= 0.06
  [PASS] Light-end contrast  #86b6ef 2.06:1  / [PASS] Single hue (spread 3°)
  → ALL CHECKS PASS

node scripts/validate_palette.js "#184f95,#256abf,#3987e5,#86b6ef" \
     --mode dark --surface "#1a1a19" --ordinal
  [PASS] Lightness monotone / [PASS] Adjacent ΔL >= 0.06
  [PASS] Light-end contrast  #184f95 2.15:1  / [PASS] Single hue (spread 3°)
  → ALL CHECKS PASS
```

### 탈락안과 사유 (실제 계산 결과)

| 안 | 검증 결과 | 탈락 사유 |
|----|-----------|-----------|
| **A. 램프 100/200/300/400** (`#cde2fb,#9ec5f4,#6da7ec,#3987e5`) | `[FAIL] Light-end contrast #cde2fb 1.29:1 — below 2:1 floor` | 가장 밝은 단계가 표면과 구분되지 않는다. 순서형은 sequential 과 달리 **가장 밝은 단계도 2:1 을 넘겨야** 한다(마크가 "거의 0"이 아니라 이산적 등급이므로) |
| **B. categorical 4색을 티어에 사용** (`#2a78d6,#eb6834,#1baf7a,#eda100`) | `[FAIL] Normal-vision floor #eda100↔#eb6834 ΔE 13.7 (<15)` + `[WARN] Contrast` | ① all-pairs 게이트를 통과하지 못한다(노랑↔주황) ② 애초에 **티어는 순서가 있는 값**이라 색상 회전은 순서를 감추는 오표현이다 |

## 2b. 상태색 — 검증 판정 (텍스트 대비 실측)

RSS 검증 판정은 **본문 크기 텍스트**로 표시하므로 차트 마크의 3:1 기준이 아니라
**WCAG 텍스트 기준(AA 4.5:1)** 으로 골랐다. 계산 결과(2026-07-30):

| 역할 | 색 | 표면 | 대비 | 판정 |
|------|----|------|------|------|
| 통과 (라이트) | `#006300` | `#fcfcfb` | 7.35:1 | AA PASS |
| 통과 (다크) | `#0ca30c` | `#1a1a19` | 5.19:1 | AA PASS |
| 탈락 (라이트) | `#d03b3b` | `#fcfcfb` | 4.68:1 | AA PASS |
| ~~탈락 (다크)~~ | ~~`#d03b3b`~~ | `#1a1a19` | 3.62:1 | **AA 미달 → 탈락** |
| 탈락 (다크) | `#e66767` | `#1a1a19` | 5.39:1 | AA PASS |
| 한글없음 경고 (라이트) | `#8a5a00` | `#fcfcfb` | 5.77:1 | AA PASS |
| 한글없음 경고 (다크) | `#fab219` | `#1a1a19` | 9.49:1 | AA PASS |

즉 다크 모드의 탈락색은 status-critical(`#d03b3b`)을 그대로 쓰지 않고 한 단계 밝은
`#e66767`(categorical red 다크 스텝)로 **의도적으로 교체**했다 — 마크가 아니라 텍스트이기 때문이다.
라이트 경고색도 마크용 `#fab219`(1.79:1) 대신 어두운 `#8a5a00`을 텍스트에 쓴다.
판정은 색 + 아이콘(✅/❌/⚠) + 수치(`9/15 · 60%`) 3중 인코딩이다.

## 3. 마크 규격

- **티어 칩**: 9×9px 라운드 스와치(2px radius) + 티어 한글 라벨. **색 단독 전달 금지** — 칩 옆에
  항상 구독자 수를 tabular-nums 로 병기한다(색·라벨·숫자 3중 인코딩).
- **분포 바**: 높이 8px, radius 4px, 세그먼트 사이 **2px 표면 간격**. 바 아래에
  스와치+라벨+개수 범례를 반드시 동반한다(바만으로는 어떤 색이 어떤 티어인지 알 수 없다).
- **진행 바**(진행 대시보드): 높이 8px, radius 4px, 트랙은 grid 토큰, 채움은 액센트.
  0%는 `min-width:0`으로 잔여 픽셀을 남기지 않는다.
- **표**: 헤어라인 구분선(grid), 마지막 행은 구분선 없음. 숫자 열은 우측 정렬 + `tabular-nums`.
- **상태(경고) 색**: `#fab219` (라이트 표면 대비 1.79:1). categorical 게이트 **비적용 대상**이며,
  3:1 미달은 **아이콘(⚠) + 라벨 문구 의무 동반**으로 면제한다(색 단독으로 의미를 싣지 않는다).
  경고 행 배경은 `color-mix(in oklab, var(--warn) 8%, transparent)` — 배경만으로 판단시키지 않는다.

### 점검 항목 (운영 콘솔)

- 좌측 3px 세로 스트라이프로 심각도를 싣고(`ok`/`warn`/`bad`/`na`), **아이콘(✅⚠️❌—) + 문구**를
  항상 동반한다. 배경 채색은 쓰지 않는다 — 점검 항목이 여러 개 쌓이면 배경색이 페이지를 지배한다.
- 각 항목은 **무엇이 문제인지(what) → 왜 문제인지(detail) → 실행할 명령(fix)** 3단으로 쓴다.
  상태만 보여주고 조치를 알려주지 않는 상황판은 반쪽이다.
- 정상 항목도 숨기지 않고 표시한다(예: "보관 정책 준수"). 무엇이 점검됐는지 알 수 있어야 한다.
- 임계값은 코드 상단 상수로 두고 근거를 `docs/PLAN.md §4b` 표에 남긴다.

### 토큰 정의점

코드 상의 단일 정의점은 `tools/_theme.py` 다 (3개 생성기가 공유). 값의 **근거와 검증 기록은
이 문서**가 소유한다. 값을 바꾸려면 이 문서 → `validate_palette.js` 재실행 → `_theme.py` 순서.

## 4. 상호작용 (내부 도구)

- 필터는 **차트/표 위 한 줄**에 모으고 sticky 로 고정한다.
- 토글 버튼은 `aria-pressed` 로 상태를 노출하고, 같은 값을 다시 누르면 해제한다.
- 검색은 채널명·핸들·채널ID를 함께 훑는다(대소문자 무시).
- 필터 결과가 0건이면 표를 숨기고 안내 문구를 보여준다 — 빈 표를 남기지 않는다.
- 포커스는 `:focus-visible` 로 2px 액센트 아웃라인.
- **외부 링크는 새 탭 + `rel="noopener"`**. 채널명·영상·정보 세 경로를 제공해
  검토자가 유튜브에서 즉시 확인할 수 있게 한다.

## 6. 서비스 UI (웹 프론트) — 확정 2026-08-03

성격: **읽는 문서가 아니라 훑고 조작하는 도구.** 요약을 먼저 주고, 상태는 색만이 아니라
형태로도 싣는다. 무엇이 새로운지·얼마나 빠른지가 한눈에 잡혀야 한다.

### 6.1 정보 구조

```
홈 /                     카테고리 선택 → 4개 보드
  └ 카테고리 내비 (칩)     확장형 체계이므로 개수가 늘어나는 전제로 가로 스크롤
  └ 형식 토글 (롱폼/Shorts) 영상 보드에만 적용
  └ 영상 보드 2 (지금 뜨는 · 신규 뜨는)
  └ 채널 보드 2 (지금 뜨는 유튜버 · 신규 뜨는 유튜버)
채널 상세 /channel/[id]  30일 성장 그래프 + 해당 채널의 급상승 영상
```

**카테고리는 탭이 아니라 칩(가로 스크롤)이다.** 탭은 개수가 고정이라는 신호를 주는데,
이 체계는 YAML 로 계속 늘어난다. 6개가 10개가 돼도 레이아웃이 깨지지 않아야 한다.

### 6.2 롱폼 / Shorts

**보드를 분리한다** (2026-08-03 실측 근거: 추적 영상의 63%가 Shorts, 산출 보드의 67% 차지).
섞으면 조회수 획득 속도가 다른 Shorts 가 롱폼을 덮는다. `trend_scores.format` 으로 분리 저장.

분리의 부수 효과로 **썸네일 비율 문제도 사라진다** — 보드마다 하나의 비율만 쓴다.

| 보드 | 타일 비율 | 그리드 |
|------|-----------|--------|
| 롱폼 | **16:9** | 데스크톱 2열 · 모바일 1열 |
| Shorts | **9:16** | 데스크톱 5열 · 모바일 3열 |

썸네일은 `object-fit: cover` + 고정 비율 박스로, 로드 전에도 레이아웃이 흔들리지 않게 한다
(CLS 방지). 유튜브 hqdefault 는 Shorts 도 16:9 레터박스라, 9:16 타일에서는 중앙 크롭한다.

### 6.3 점수 표현 — 원시 숫자를 노출하지 않는다

산출 점수(`5313.57` 같은 값)는 사용자에게 아무 의미가 없다. 대신 **검증 가능한 사실**을 보여준다.

```
┌ 3  [썸네일]  제목 두 줄까지…
│              채널명 · 조회수 12.4만
│              ▍▍▍▍▍▍▍░░░   48시간 +8.2만
└
```

- **주 표기**: `{구간}시간 +{Δ조회수}` — 실측값이고 사용자가 확인할 수 있다
- **보조 표기**: 보드 1위 대비 상대 강도 막대 (해당 보드 안에서만 정규화)
- **원시 점수는 노출하지 않는다.** 툴팁·상세에도 넣지 않는다 — 단위 없는 수는 신뢰를 주지 않는다
- 순위 숫자는 색이 아니라 **크기·굵기**로 강조한다 (1~3위만 강조, 나머지는 뮤트)

### 6.4 색

§1 토큰을 그대로 쓴다. 서비스 UI 가 추가로 요구하는 것은 **보드 구분 2색**뿐이다.

| 역할 | 라이트 | 다크 |
|------|--------|------|
| 지금 뜨는 (trending) | `#2a78d6` | `#3987e5` |
| 신규 뜨는 (rising) | `#eb6834` | `#d95926` |

검증 기록 (2026-08-03, `--pairs all`):

```
light  surface #fcfcfb : [PASS] band · chroma · CVD ΔE 24.7(protan)/32.7(tritan)
                         · normal ΔE 33.6 · contrast >= 3:1   → ALL PASS
dark   surface #1a1a19 : [PASS] band · chroma · CVD ΔE 26.8/32.4
                         · normal ΔE 31.8 · contrast >= 3:1   → ALL PASS
```

**카테고리에는 색을 쓰지 않는다.** 6개가 계속 늘어나므로 categorical 게이트를
언젠가 반드시 깬다(팔레트 문서상 all-pairs 는 3슬롯까지만 안전). 카테고리는 **라벨과 선택
상태**로만 구분한다 — 색을 아껴 보드 구분에만 쓴다.

강도 막대는 보드 색의 단일 색상 채움 + `--grid` 트랙이다. 순서형 램프가 아니라
**하나의 값을 비율로 보여주는 것**이므로 단색으로 충분하다.

### 6.5 타이포그래피

**Pretendard 한 벌 + 굵기·크기 대비.** 한국어에서 디스플레이 서체를 따로 얹으면 본문과
질감이 어긋나기 쉽고, 웹폰트 용량도 배가 된다. 흔한 "디스플레이 세리프 + 본문 산세리프"
조합은 한글에서 잘 작동하지 않으므로 의도적으로 피한다.

| 역할 | 규격 |
|------|------|
| 페이지 제목 | 28px / 700 / `text-wrap: balance` |
| 보드 제목 | 17px / 650 + 보드 색 점(8px) |
| 카드 제목 | 14.5px / 600 / 2줄 클램프 |
| 메타(채널·조회수) | 12.5px / 500 / `--ink-2` |
| 숫자 | `font-variant-numeric: tabular-nums` — 목록에서 자릿수가 흔들리지 않게 |

본문 길이는 65자 내외를 넘기지 않는다(카드 제목은 클램프로 강제).

### 6.6 채널 상세 그래프

dataviz form heuristic: **시간에 따른 변화 → 선형(line)**. 임의 선택이 아니다.

- **구독자 추이**와 **총 조회수 추이**를 **각각 별도 차트**로 그린다.
  **이중 축(dual-axis)은 쓰지 않는다** — 척도가 다른 두 값을 한 축에 겹치면 관계를 오독한다.
- 단일 시리즈이므로 범례를 두지 않는다(제목이 시리즈를 지칭한다).
- 선 2px, 마지막 점을 6px 로 강조, 영역 채움은 선 색 12% 투명도.
- 그리드는 가로선만, `--grid` 헤어라인. 축 라벨은 `--muted`.
- **스냅샷이 2개 미만이면 차트를 그리지 않고 "데이터 축적 중" 문구를 보여준다.**
  빈 축만 있는 차트는 장애처럼 보인다.

### 6.7 문구 규칙

- 점수 옆에는 항상 **"자체 산출 급상승 지표"** 고지를 둔다. 유튜브 공식 지표가 아니다.
- 보드 이름은 사용자의 말로 쓴다: "지금 뜨는 영상" / "새로 뜨는 영상"
  (내부 용어인 trending·rising·velocity 를 화면에 노출하지 않는다)
- 빈 보드는 사과하지 않고 **이유와 다음 상태**를 말한다:
  "아직 이 카테고리의 급상승 영상이 없습니다 — 수집이 쌓이면 채워집니다"
- 시간 표기는 상대값("3시간 전")을 쓰되 `title` 속성에 절대 시각을 남긴다.

### 6.8 YouTube 표기 (ToS)

- 카드 전체가 유튜브 링크다. `target="_blank" rel="noopener"`.
- 재생은 **유튜브에서** 한다 — 임베드 플레이어를 두지 않는다.
- 썸네일은 유튜브 CDN 원본을 그대로 참조한다(재호스팅·가공 금지).
- 푸터에 데이터 출처와 자체 지표 고지, 개인정보처리방침 링크를 둔다.

### 6.10 접근성 체크리스트 (배포 전 게이트)

- [x] 보드 구분을 색만으로 하지 않는다 — 제목·설명 문구 동반
- [x] 순위는 색이 아니라 숫자·크기로 표현 (1~3위만 크게)
- [x] 라이트/다크 각각 검증 (§6.4 기록)
- [x] 카드 링크에 접근 가능한 이름 (제목 텍스트가 곧 링크명)
- [x] 키보드 포커스 가시 상태 (`:focus-visible` 2px 액센트)
- [x] 이미지 고정 비율 박스(`aspect-ratio`)로 CLS 방지
- [x] `prefers-reduced-motion` 존중
- [x] 본문 가로 스크롤 없음, 칩 내비만 자체 스크롤
- [x] 강도 막대에 `role="img"` + `aria-label` (수치를 읽어준다)

**썸네일 `alt` 규칙 (2026-08-03 수정)**: 최초 규격은 "제목을 alt 에 넣는다"였으나,
구현에서 카드 구조를 바꾸면서 규칙을 바꿨다. 카드 전체를 `<a>` 로 감싸면 채널 링크가
**앵커 중첩**이 되어 유효하지 않은 HTML 이 된다. 그래서 썸네일·제목·채널을 각각 독립 링크로
분리했고, 그 결과 **썸네일 링크와 제목 링크가 같은 목적지**가 됐다.
이때 썸네일에 제목을 다시 넣으면 스크린리더가 같은 내용을 두 번 읽는다.
→ 썸네일 링크는 `aria-hidden` + `tabindex="-1"` + `alt=""` 로 두고, **제목 링크가 접근 가능한
이름을 담당**한다. 탭 이동도 카드당 한 번만 멈춘다.
